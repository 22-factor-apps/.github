# Support

Use the repository that owns the affected boundary:

- Site content, catalog, template, or Pages deployment: `22-factor-apps.github.io`
- CLI behavior, policy cues, schemas, or assessment validation: `22-factor-apps-audit`
- Organization profile or shared policy: `.github`

Public issues are appropriate for non-sensitive bugs and proposals. Use private
vulnerability reporting for anything that might expose credentials, repository
metadata, assessment evidence, or deployment internals.
